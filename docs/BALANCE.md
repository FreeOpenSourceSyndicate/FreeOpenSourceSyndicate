# Balance — the campaign's tuning curve

> **AI/LLM-generated document.** This file was generated by an AI agent and is not
> human-written source documentation.

This is the target curve for the v1.0.0 campaign: what the shipped
`assets/data/world/**` numbers are *trying* to achieve, and which test pins the
relationship so a later edit cannot silently break it. It is a **first pass**
(issue #528, the Milestone C "Balance pass" DoD item); a deeper pass can follow
the maintainer's v0.9.0 playtest.

The values live in data (ADR-0003, golden rule 7) — retune them by editing the
JSON, never by adding a C++ constant. Every pin below reads the **shipped** files
(not a hard-coded copy), so the tests fail if the data drifts.

## 1. The loop and its clock

A campaign tick is `EconomyConfig::tickSeconds` in-game seconds (30 s shipped).
Every tick:

1. Each owned region pays `baseIncome + incomePerTaxLevel * taxLevel` to its owner.
2. Each region taxed at or above `revoltThresholdLevel` rolls `revoltChancePerTick`
   to flip back to neutral at tax 0.

So the whole metagame is "hold regions → tax them → bank income → fund research →
buy gear → deploy → win the mission → hold more regions". The balance question is
whether that loop closes in a number of ticks a player will actually play.

## 2. The economy (shipped `campaign.json`)

| Knob | Value | Why |
|------|-------|-----|
| `startingFunds` | 1000 | buys the cheapest research root on turn one, so the opening never stalls |
| `baseIncome` | 0 | an untaxed region pays nothing — holding is not enough, you must tax |
| `incomePerTaxLevel` | 60 | the spine: one tax level, one region = 60 funds/tick |
| `maxTaxLevel` | 5 | the risky ceiling |
| `revoltThresholdLevel` | 3 | tax 0–2 is safe; 3–5 can revolt |
| `revoltChancePerTick` | 0.06 | makes over-taxing a real gamble (see below) |
| `tickSeconds` | 30 | the in-game seconds per tick |

**Income per tick.** With `baseIncome` 0, a region's income is
`60 * tax`. The starting position (two owned regions, safely taxed at 2) is
therefore **240 funds/tick**. The fully-taxed end game (twelve regions at tax 5)
is **3600 funds/tick** — the economy scales with the map, so late-game purchases
do not require grinding early regions.

**The tax-vs-revolt trade-off.** At `revoltChancePerTick` 0.06, the risky max tax
(5) out-earns the safe tax (2) only over a short horizon: it stops paying after
roughly 38 ticks, well inside a campaign. So the *gamble is live but not a trap* —
a player who plans ahead de-escalates. (At the old 0.02 it dominated for ~112
ticks, which is no decision at all.)

## 3. Research pacing (shipped `research.json`)

The tree is an eleven-node, three-tier progression plus three drug-ceiling roots
(ADR-0043): a cheap tier-1 node (`minigun`, and the four cybernetics and three
ceilings), a branch (`gauss`/`longshot`), and a top node (`railgun`) gated behind
both branches.

| Target | Value |
|--------|-------|
| Per-node cost | 500–1600 |
| Per-node time | 45–150 s |
| Whole-tree cost | 7600 |
| Whole-tree time | 795 s ≈ 27 ticks |
| Ticks to afford the whole tree from the start | ~28 |

Every root node is affordable on turn one; the top node is a few ticks away; the
whole tree is a couple of dozen. The campaign's win needs neither the whole tree
nor the top squad, so ~28 ticks is the theoretical ceiling, not the route.

## 4. Weapon and equipment price ladder (shipped `equipment.json`)

A player pays for **reach and punch**, not for a name. The total cost of a
weapon — its research node plus the catalogue item — must rise with its combat
value (`damage * range`), so the more expensive gun is never the weaker one:

| Weapon | Research | Item | Total | `damage * range` |
|--------|---------:|-----:|------:|-----------------:|
| `minigun` | 500 | 500 | 1000 | 24 |
| `gauss` | 700 | 700 | 1400 | 77 |
| `longshot` | 900 | 900 | 1800 | 210 |
| `railgun` | 1600 | 1600 | 3200 | 442 |

`gauss` and `longshot` are both tier-2 (behind `minigun`), so the ladder is
`minigun < gauss < longshot < railgun` in *both* combat value and total cost. The
first pass (#419) had this pair **inverted** — `gauss` cost more (1800) than
`longshot` (1400) while reaching less and hitting softer — so a player who saved
up was punished. This pass swaps the pair (and their research times) so the price
tracks the gun; both tree sums (7600 cost / 795 time) are unchanged.

Pin: `tests/test_research.cpp` — `ShippedWeaponLadderCostsTrackCombatValue`
(fails under the pre-#528 inversion).

**Open (Rule 4 → `content`/`tactical`).** The `minigun`'s raw DPS (32) is the
highest in the catalogue — it is a *cheap tier-1* gun whose DPS beats the tier-2
and tier-3 rifles, which makes the ladder's *damage* axis (not its cost axis)
incoherent. `weapons.json` is `focus: content`/`tactical` (`src/core/sim/Weapon.h`
is Tactical's), so retuning the weapon **stats** is a Rule 4 request, not part of
this metagame pass. Filed separately.

## 5. What "winnable but not trivial" means

- **Winnable:** `--check-campaign`'s self-test and
  `Campaign.ShippedCampaignCanBeWonByClaimingTheFrontier` walk the real
  deploy → win → claim loop to a full map, so a data edit that soft-locks the
  campaign (e.g. a region no one can reach) fails a test, not a playtest.
- **Not trivial:** the whole tree is ~27 ticks of income and the top squad is
  ~15 ticks, so a player must actually play the map (tax, deploy, win) rather
  than buy their way to the end on the starting funds.
- **Not a grind:** the twelve-region map scales income to 3600/tick when fully
  taxed, so the late game is fast; no single node or item costs a whole campaign.

## 6. Changing these numbers

1. Edit the JSON in `assets/data/world/**` (data, not code).
2. Run `ctest` — the pins above fail if a relationship breaks.
3. If a pin is genuinely wrong (the curve changed on purpose), update the pin
   **and** this file in the same PR, and say why.
4. A weapon-*stat* change (damage/range/rate/accuracy) is not this area's:
   `assets/data/weapons.json` is `focus: content`, `src/core/sim/Weapon.h` is
   `focus: tactical`. File a Rule 4 request.
