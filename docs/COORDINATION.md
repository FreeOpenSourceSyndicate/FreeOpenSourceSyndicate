# Multi-Agent Coordination

FOSSynd is developed by several AI agents (and humans) working in parallel. This
page is the whole protocol. `AGENTS.md` is the rulebook; `docs/FOCUS_AREAS.md` is
the assignment sheet (which files each of the nine focus areas owns).

**There is no coordinator** (ADR-0019). Coordination is **flat**, and it is now
**machine-checked**: a claim is a **git ref**, not a comment (ADR-0021). Read this
page, run three commands, and you are coordinated.

## TL;DR

```bash
# 0. Not sure what to do? Ask. This never returns nothing.
scripts/coord next --agent "Claude Sonnet 4.5"

# 1. See what is taken and what is free.
scripts/coord status

# 2. Take a free area for one task. The area is the lock.
scripts/coord claim --area world --issue 157 --agent "Claude Sonnet 4.5" --branch feat/world-destructible

# 3. Work. If you are still going when the lease nears its TTL, extend it.
scripts/coord renew  --area world --issue 157 --agent "Claude Sonnet 4.5"

# 4. Done (merged or abandoned): give the area back early.
scripts/coord release --area world --issue 157 --agent "Claude Sonnet 4.5"
```

That is the entire coordination overhead. No check-in, no hub comment, no one to
ask.

## 1. The model in one paragraph

A **file has exactly one owning focus area** (`docs/FOCUS_AREAS.md` §2), so two
agents can collide on a file only by holding the **same area**. The area is
therefore the only lock the fleet needs, and the lease is keyed by **area**, not
by issue: a git ref `refs/coord/leases/<area>` whose target is a tiny JSON record
with an expiry (`epoch + ttl`). Keying by issue would be a bug — two agents
claiming different issues in one area would CAS different refs and both win.
Taking a lease is `git push --force-with-lease`, which is an **atomic
compare-and-swap** — if two agents race, exactly one wins. A lease that reaches
its expiry is **dead**, and the area is claimable again with no human involved.
This is what makes the fleet safe when an agent **stops mid-work or pauses for an
unreasonably long time**: it cannot renew, so its lease ages out, and nobody was
ever waiting on it.

## 2. Claiming, renewing, releasing

The tool is `scripts/coord` (Python 3, stdlib only; needs a `git` binary). Every
command talks to the shared remote `origin`; you never edit a file by hand.

### Claim an area

```bash
scripts/coord claim --area <area> --issue <n> --agent "<model>" --branch <branch>
```

- **`--area`** is one of the nine focus areas: `tactical`, `world`, `render`,
  `input-ui`, `content`, `text`, `metagame`, `platform`, `release`.
- **One task = one branch = one PR.** Claim the area for the *task* you are about
  to do; the issue is what makes the claim legible.
- The default TTL is **6 h**, capped at **24 h** (`--ttl 90m`, `--ttl 6h`, ...).
- If the area is already held by a **live** lease, the claim **fails** and tells
  you who holds it and for how long. Pick a free area, or wait.
- **`--takeover`** claims anyway. Use it when the holder is gone — but it is
  *announced*, never silent: it prints whose lease you replaced. Taking over a
  live lease is allowed (the holder may have paused); taking over a **stale** one
  (> 3 h quiet) is expected.

### Keep it alive

```bash
scripts/coord renew --area <area> --issue <n> --agent "<model>"
scripts/coord renew --area <area> --issue <n> --agent "<model>" --state blocked --note "waiting on #120"
```

Renewal is one ref update — cheap. Renew whenever you would otherwise cross the
TTL; do not rely on a long TTL to cover a long task. `--state` sets
`claimed` (default), `blocked`, or `needs-review`, which shows on the board and
drives the `status:` labels.

### Give it back

```bash
scripts/coord release --area <area> --issue <n> --agent "<model>"
```

Release as soon as your PR is **merged**, and also when you **abandon** the task.
An abandoned lease you do not release is reclaimed by the TTL — but releasing is
polite and instant. A merged PR should be followed by a release in the same
breath.

## 3. What to do when you are blocked

1. **Another agent holds the area you want.** Read `scripts/coord status`; pick
   the **next free area** with pending work. You do **not** wait for the holder.
2. **You need a change in another area's files.** Do not edit them. File a
   cross-area request (`docs/FOCUS_AREAS.md` §4, Rule 4) and work on something
   else; the owner (or, if the area is free, you) picks it up.
3. **You hit a genuinely human question** (product direction, licensing, a rule
   change, release policy). Post it **yourself** on the issue thread, tagged
   `question` + `status: blocked`, with options and a recommendation, and continue
   on the reversible path if one exists. There is **no relay** and no waiting
   silently (`docs/FOCUS_AREAS.md` §5.2).

## 3a. Never idle: `coord next`

An agent that does not know what to do runs one command:

```bash
scripts/coord next --agent "<model>"
```

It **never prints nothing**. It walks a fixed ladder and stops at the first rung
that applies, so there is always a next step:

1. **You hold a lease** → finish it, or `renew`/`release` it.
2. **A critical-path area is free** (`metagame`, `tactical`; `docs/ROADMAP.md`)
   → claim its newest open issue.
3. **Any free area has an open issue** → claim the newest such issue.
4. **The backlog is empty** → it prints the first unchecked `docs/ROADMAP.md`
   items and tells you to **file an issue** (with a `focus: <area>` label) and
   claim it. This is the fleet's only stop condition, and the fix is to **add
   work, not agents** (`AGENTS.md` §1d, ADR-0024).
5. **Every area is held** → it points at a **stale** holder to take over, or, if
   none is stale, at the fleet's other durable job: **review and merge an open PR
   you did not author** (`AGENTS.md` §3a).

Rungs 4 and 5 are what make the fleet self-sustaining: even with every area
taken and no issue filed, an agent is told to create work or to review, never to
wait.

## 4. The board

`docs/COORDINATION_BOARD.md` is **generated** from the ledger:

```bash
scripts/coord board --stdout      # print it
scripts/coord board               # regenerate the file
```

It is a **view**, never an authored document — do **not** hand-edit it, and do
**not** open a "refresh the queue" PR. The scheduled workflow rewrites it on every
sweep. It shows, per area: the holder, the state, and the TTL remaining.

## 5. The sweep (automatic)

`.github/workflows/coordination.yml` runs every 30 minutes (and on demand):

- **deletes** expired lease refs,
- **syncs** the `status:` labels and a convenience claim comment on GitHub, and
  **clears** a lease-set `status: claimed` left on an *open* issue with no live
  lease behind it (a released lease) — so the mirror never drifts. It does **not**
  touch `status: blocked` / `status: needs-review` (they also mark human questions
  and Rule 4 requests, which have no lease) and does **not** rewrite closed
  issues (history stays as-is),
- **regenerates** the board and commits it when it changed.

You never run this by hand; you never have to notice a dead agent. A lease that
nobody renews simply disappears and its area becomes claimable.

The same workflow runs `scripts/coord check` as a **hard gate** on relevant
PRs/pushes: two live leases may never collide on an area or an issue. A
coordination regression fails CI like any other bug.

## 6. Review and merge (unchanged)

Coordination changed; **review policy did not**. Keep the queue moving:

- **Review and merge PRs you did not author** (`AGENTS.md` §3a). A stale green PR
  is a bug.
- **Sole-account exception:** while this repo has a single GitHub account, an
  agent may review and merge its own PR — do the review honestly and say which
  model merged it.
- **Adopt an orphaned PR** (author gone quiet, CI green): review and merge it.
  With leases, "gone quiet" is now visible on the board as a **stale** holder.
- **Rules-doc PRs** (`AGENTS.md`, `COORDINATION.md`, `FOCUS_AREAS.md`,
  `DECISIONS.md`) need **two peer reviews**, or an explicit self-review against the
  checklist in `docs/FOCUS_AREAS.md` §6.

## 7. The nine focus areas

The areas are the lock (full file map: `docs/FOCUS_AREAS.md` §2):

| Area | `focus:` label | Owns (summary) |
|------|----------------|-----------------|
| Tactical / Mission | `focus: tactical` | `core/sim` mission, combat, weapons, objectives; `assets/data/missions` |
| World / Simulation | `focus: world` | `core/world`, `core/math`, `core/util`, `core/sim/Agent` |
| Render / Engine | `focus: render` | `src/game` drawing, HUD, minimap, sprites, font |
| Input / UI / UX | `focus: input-ui` | `src/main.cpp`, input/selection, CLI flags |
| Content / Data | `focus: content` | `core/data`, `assets/data` (except missions) |
| Text / i18n / Lore | `focus: text` | `core/i18n`, `assets/lang`, lore |
| Metagame / Campaign | `focus: metagame` | `core/economy` (world map, economy, research, purchase, campaign), the map/management screen |
| Build / CI / Tooling | `focus: platform` | `.github`, CMake, `scripts`, deps, packaging |
| Release / Playtest | `focus: release` | `CHANGELOG.md`, `docs/releases`, banners, tags |

The fleet size **varies (1–10)**; the scheme does not care. With one agent, claim
any area. With ten, `scripts/coord status` shows the free ones and the fleet fans
out. Nobody assigns anything.

## 8. Why this is safe with unreliable agents

| Failure | What happens now |
|---------|------------------|
| An agent crashes mid-task | Its lease ages out in ≤ 24 h; the area frees itself. No peer or human has to notice. |
| An agent pauses for hours | Same: the TTL is the safety net. If it resumes before expiry, it renews. |
| Two agents race for one area | `git push --force-with-lease` is atomic: exactly one wins, the loser is told who holds it. |
| An agent forgets to release | The TTL reclaims it; a sweep deletes the ref. |
| An agent is unsure whether an area is free | `scripts/coord status` is authoritative; it is the ledger, not a comment. |
| Two agents both believe they own an area | They cannot: `coord check` fails CI on a collision, and the ledger has one ref per area. |
| A hand-written queue goes stale | There is no hand-written queue; the board is generated. |

## 9. Migration from the old comment protocol

If you are an agent that was already mid-cycle under the old `CLAIM:` comment
protocol, nothing is lost. See `docs/COORDINATION_MIGRATION.md`. In short:

```bash
scripts/coord migrate --issues <n> <n> ...     # import live legacy claims as leases
```

The tool still **reads** legacy `CLAIM:`/`LEASE:`/`TAKEOVER:` lines, so a claim
posted by a not-yet-updated agent is honoured during the transition.

## 10. What "good" looks like

- `main` is always green, and `coord check` is green.
- Every merge is traceable to an issue and an agent.
- Every area in flight has **exactly one** live lease; the board shows it.
- No agent waits on a missing one: an area whose holder is gone frees itself.
- Nobody hand-edits the board or opens a "refresh the queue" PR.
- A human question goes straight from the asking agent to the human — no relay.
- New agents read `AGENTS.md` + this page and are productive in one sitting.
