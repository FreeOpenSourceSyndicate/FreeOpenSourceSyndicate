# Multi-Agent Coordination

FOSSynd is developed by several AI agents (and humans) working in parallel. This
page is the **lease protocol**. `docs/ORGANISATION.md` is the top-level sheet
(roles, agent names, per-host rosters, channels, takeover); `AGENTS.md` is the
rulebook; `docs/FOCUS_AREAS.md` is the assignment sheet (which files each focus
area owns). Read `docs/ORGANISATION.md` first, then this page.

**There is no coordinator** (ADR-0019). Coordination is **flat**, and it is now
**machine-checked**: a claim is a **git ref**, not a comment (ADR-0021). Read this
page, run three commands, and you are coordinated.

Agents are **named** `<role>-<n>-<host>` (e.g. `ta-1-kastenbrot`), recorded on a
per-host **roster** (`scripts/coord agent --list`). Use your name — not a bare
model string — as `--agent` (docs/ORGANISATION.md §3).

## TL;DR

```bash
# 0. Register your name once per session (see docs/ORGANISATION.md §3-4).
scripts/coord agent --register --role wo --model "Claude Sonnet 4.5"
#    -> wo-1-<your host>   (the host defaults to $COORD_HOST, else the hostname)

# 0b. Not sure what to do? Ask. This never returns nothing.
scripts/coord next --agent "wo-1-kastenbrot"

# 1. See what is taken and what is free.
scripts/coord status

# 2. Take a free area for one task. The area is the lock.
scripts/coord claim --area world --issue 157 --agent "wo-1-kastenbrot" --branch feat/world-destructible

# 3. Work. If you are still going when the lease nears its TTL, extend it.
scripts/coord renew  --area world --issue 157 --agent "wo-1-kastenbrot"

# 4. Done (merged or abandoned): give the area back early, then leave a note.
scripts/coord release --area world --issue 157 --agent "wo-1-kastenbrot"
scripts/coord note --area world --agent "wo-1-kastenbrot" --text "handoff: ..."
```

That is the entire coordination overhead. No check-in, no hub comment, no one to
ask. Your **name** is `<role>-<n>-<host>` (`docs/ORGANISATION.md` §3) — not a
model string — so two same-model workspaces are distinguishable.

## 1. The model in one paragraph

A **file has exactly one owning focus area** (`docs/FOCUS_AREAS.md` §2), so two
agents can collide on a file only by holding the **same area**. The area is
therefore the only lock the fleet needs, and the lease is keyed by **area**, not
by issue: a git ref `refs/coord/leases/<area>` whose target is a tiny JSON record
with an expiry (`epoch + ttl`). Keying by issue would be a bug — two agents
claiming different issues in one area would CAS different refs and both win.
Taking a lease is `git push --force-with-lease`, which is an **atomic
compare-and-swap** — if two agents race, exactly one wins. A lease that reaches
its expiry is **dead**, and the area is claimable again with no human involved.
This is what makes the fleet safe when an agent **stops mid-work or pauses for an
unreasonably long time**: it cannot renew, so its lease ages out, and nobody was
ever waiting on it.

## 2. Claiming, renewing, releasing

The tool is `scripts/coord` (Python 3, stdlib only; needs a `git` binary). Every
command talks to the shared remote `origin`; you never edit a file by hand.

### Claim an area

```bash
scripts/coord claim --area <area> --issue <n> --agent "<role>-<n>-<host>" --branch <branch>
```

- **`--area`** is a focus area from `docs/focus-areas.json` (or a channel: `sm`,
  `po`, `takeover`). The set is data, not code (docs/ORGANISATION.md §9). Today:
  `tactical`, `missions`, `world`, `render`, `input-ui`, `content`, `text`,
  `metagame`, `platform`, `rules`, `release`. **`rules` is the SM's own lane**: the SM
  triggers it and `coord next` never routes a plain worker to it. **`platform` is
  a normal worker lane** (ADR-0041): build/CI/packaging routes to a `pf` worker,
  never to the SM.
- **One task = one branch = one PR.** Claim the area for the *task* you are about
  to do; the issue is what makes the claim legible.
- The default TTL is **6 h**, capped at **24 h** (`--ttl 90m`, `--ttl 6h`, ...).
- If the area is already held by a **live** lease, the claim **fails** and tells
  you who holds it and for how long. Pick a free area, or wait.
- **`--takeover`** claims anyway. Use it when the holder is gone — but it is
  *announced*, never silent: it prints whose lease you replaced. Taking over a
  live lease is allowed (the holder may have paused); taking over a **stale** one
  (> 2 h quiet) is expected.

**Identity is agent *and* branch** (ADR-0034). `--agent` is your *model* name,
which is not unique — two workspaces on the same model share it. So a lease
counts as **yours** only when the `agent` matches **and** the `branch` it records
is the branch you are on; `next` will not report a same-named peer's lease as
yours, and `renew`/`release` will not let you free it. A lease with no `--branch`
(legacy) still matches by name alone. If you must renew or release from a
different branch, name the branch explicitly (`--branch <branch>`), or use
`--force`.

### Keep it alive

```bash
scripts/coord renew --area <area> --issue <n> --agent "<role>-<n>-<host>"
scripts/coord renew --area <area> --issue <n> --agent "<role>-<n>-<host>" --state blocked --note "waiting on #120"
```

Renewal is one ref update — cheap. Renew whenever you would otherwise cross the
TTL; do not rely on a long TTL to cover a long task. `--state` sets
`claimed` (default), `blocked`, or `needs-review`, which shows on the board and
drives the `status:` labels.

### Give it back

```bash
scripts/coord release --area <area> --issue <n> --agent "<role>-<n>-<host>"
```

Release as soon as your PR is **merged**, and also when you **abandon** the task.
An abandoned lease you do not release is reclaimed by the TTL — but releasing is
polite and instant. A merged PR should be followed by a release in the same
breath.

## 3. What to do when you are blocked

1. **Another agent holds the area you want.** Read `scripts/coord status`; pick
   the **next free area** with pending work. You do **not** wait for the holder.
2. **You need a change in another area's files.** Do not edit them. File a
   cross-area request (`docs/FOCUS_AREAS.md` §4, Rule 4) and work on something
   else; the owner (or, if the area is free, you) picks it up.
   If **your own** issue cannot start until that request lands, mark it
   `status: blocked` **and** add a `blocked-by: #<n>` line to its body (several
   numbers per line allowed: `blocked-by: #311, #312`). The scheduled `sweep`
   clears `status: blocked` automatically once **every** referenced issue is
   closed, so the block lifts itself — no agent has to remember (ADR-0030). An
   issue with no `blocked-by:` line is never touched, which is what keeps the
   §3.3 human-question use of `status: blocked` safe.
3. **You hit a genuinely human question** (product direction, licensing, a rule
   change, release policy). Post it **yourself** on the issue thread, tagged
   `question` + `status: blocked`, with options and a recommendation, and continue
   on the reversible path if one exists. There is **no relay** and no waiting
   silently (`docs/FOCUS_AREAS.md` §5.2).

## 3a. Staying in lane: `coord next`

An agent that does not know what to do runs one command:

```bash
scripts/coord next --agent "<role>-<n>-<host>"
```

**An agent keeps its scope small and stays in its lane; an empty lane is a stop
(ADR-0046).** `coord next` reports, in order, the only things an idle agent may
do — and prints **stop** when none applies:

1. **You hold a lease** → finish it, or `renew`/`release` it.
1b. **You are the SM and your own lane is free** (`rules`; `docs/ORGANISATION.md`
    §7) → claim its newest open issue. The SM triggers its own coordination work;
    a plain worker is never routed here, and the SM is never routed to a worker's
    lane (ADR-0041).
2. **A critical-path area is free** (`tactical`, `missions`, `metagame`,
   `input-ui`, `render` — `docs/ROADMAP.md`; reordered by the PO on 2026-10-17)
   → claim its newest open issue.
3. **A green PR has waited** (non-draft, merge state `CLEAN`, open ≥ 30 min)
   → review and merge it (`AGENTS.md` §3a). A green PR is *finished* work one
   step from landing: merging it is worth more than *starting* new work, which
   commits a cycle and risks orphaning the PR that was already done. This is how
   the queue drains without a coordinator (ADR-0035). It never preempts a waiting
   blocker or the critical path (rung 2).
4. **Nothing above applies** → it prints **stop**. The agent ends its turn.

Rungs 4–5 of the old ladder — "claim **any** free area's issue" and "**file a new
issue** when the backlog is empty" — are **removed**: they pushed agents out of
their lane and into larger scope (the helper-lease trap, five times in one shift),
and an empty lane is a **stop**, not a signal to seed work. The fleet's only
stop condition is now the agent's own lane being empty. (ADR-0046; the
`scripts/coord next` code change is a `focus: platform` Rule 4.)

Rung 3 is what keeps the fleet's shared duty alive: even with every area taken, an
agent is told to drain the merge queue — finished work one step from landing —
rather than to start more. It never tells an agent to wait, and it no longer tells
one to go find work in another lane.

**Only claimable work is offered.** Rungs 1b and 2 read open issues by their
`focus:` label and skip any that are not claimable — `status: blocked` (waiting on
another area), `question` (a human decision, §5.2), and `deferred: v2` (out of v1.0.0
scope, ADR-0024). A **Rule 4 request** (`status: needs-review`) is marked a
*blocker*: another lane is *waiting* on it (§4 Rule 4), so it is offered **before**
plain work — within its area, and across the critical path, where a waiting
blocker in any free critical-path area outranks plain work in the first one.
Clearing a blocker unblocks a peer, so an agent is never steered to work it cannot
start, nor past a blocker that is holding a peer.

## 3b. Handoff notes (survive the lease)

A lease is scoped to **now**: it is deleted on release and ages out on TTL, so a
fact the *next* process needs has nowhere to live. Notes are that place.

```bash
scripts/coord note  --area world --agent "<role>-<n>-<host>" \
    --text "push auth was stale; run gh auth setup-git first"
scripts/coord notes --area world      # read one area
scripts/coord notes                   # read every area
```

- Notes are keyed by **area**, exactly like leases, and stored as git refs
  (`refs/coord/notes/<area>`) with the same flat, server-free shape.
- They are **append-only and never expire** — releasing or expiring a lease does
  not remove its notes. Read them before you start an area.
- They are **not a lock**: a note never blocks a claim, and writing one never
  takes or holds a lease. Two agents appending at once both keep their note.
- Only the most recent `MAX_NOTES` (20) per area are kept.
- The generated board prints every area's notes under **Handoff notes**, so a
  fresh process sees the handoff without running a command.

**Channels.** The key is not only a focus area: the process roles have their own
append-only topics (ADR-0037, docs/ORGANISATION.md §5):

```bash
scripts/coord note --area sm --agent sm-1-kastenbrot --text "handoff: ..."
scripts/coord notes --area sm      # SM <-> SM, across hosts and over time
scripts/coord notes --area po      # PO <-> PO
scripts/coord takeover             # open takeover requests
```

`sm` and `po` carry the cross-machine handoff (docs/ORGANISATION.md §6b); the
`takeover` channel carries takeover requests (§3c below). A channel note is
exactly as harmless as an area note: never a lock, never an assignment.

**Direct messages.** A channel is for a role or the fleet; for a one-to-one
exchange address **one named agent** directly (ADR-0037, docs/ORGANISATION.md
§5). A generated prompt is needed only to *start* a chat that does not exist yet;
after that, agents talk to each other and never route ordinary coordination
through the human:

```bash
scripts/coord msg --to ta-1-kastenbrot --agent po-2-kastenbrot --text "use escort.json"
scripts/coord inbox --agent ta-1-kastenbrot     # read yours
```

Messages live at `refs/coord/msg/<agent>`: append-only, never expiring, never a
lock — the same shape as a note, but private to the recipient (not printed on the
board, not filed under an area). A message to an invalid agent name is refused.

## 3c. Taking over a quiet holder

A lease live but quiet for more than `STALE_AFTER` (**2 h**) is **stale** — its
holder may still be working, so the clock, not a peer's judgement, decides. Two
ways to reclaim it:

```bash
# Cooperative: ask the fleet to pick the area up (cheap, leaves a trail).
scripts/coord takeover --request --area world --agent sm-1-kastenbrot
scripts/coord takeover                  # any idle agent reads the open requests

# Direct: announce and take the lease (never silent).
scripts/coord claim --area world --issue 157 --agent wo-1-kastenbrot \
    --branch feat/world-save-load --takeover
```

`coord next` offers an open request for a now-free area **before** draining the
merge queue, so a request is not left unread. Rules of thumb, and how the SM
tunes the window, are in `docs/ORGANISATION.md` §6a.

Use a note when the next process would otherwise re-discover something the hard
way: broken tooling, a decision that should not be re-litigated, a warning about
a trap in an area. Do **not** use it as a queue or an assignment — that is what
issues are for.

## 4. The board

`docs/COORDINATION_BOARD.md` is **generated** from the ledger:

```bash
scripts/coord board --stdout      # print it
scripts/coord board               # regenerate the file
```

It is a **view**, never an authored document — do **not** hand-edit it, and do
**not** open a "refresh the queue" PR. The scheduled workflow rewrites it on every
sweep. It shows, per area: the holder, the state, and the TTL remaining.

## 5. The sweep (automatic)

`.github/workflows/coordination.yml` runs every 30 minutes (and on demand):

- **deletes** expired lease refs,
- **syncs** the `status:` labels and a convenience claim comment on GitHub, and
  **clears** a lease-set `status: claimed` left on an *open* issue with no live
  lease behind it (a released lease) — so the mirror never drifts. It does **not**
  touch `status: blocked` / `status: needs-review` (they also mark human questions
  and Rule 4 requests, which have no lease) and does **not** rewrite closed
  issues (history stays as-is),
- **regenerates** the board and commits it when it changed.

You never run this by hand; you never have to notice a dead agent. A lease that
nobody renews simply disappears and its area becomes claimable.

The same workflow runs `scripts/coord check` as a **hard gate** on relevant
PRs/pushes: two live leases may never collide on an area or an issue. A
coordination regression fails CI like any other bug.

## 6. Review and merge (unchanged)

Coordination changed; **review policy did not**. Keep the queue moving:

- **Review and merge PRs you did not author** (`AGENTS.md` §3a). A stale green PR
  is a bug.
- **Sole-account exception:** while this repo has a single GitHub account, an
  agent may review and merge its own PR — do the review honestly and say which
  model merged it.
- **Adopt an orphaned PR** (author gone quiet, CI green): review and merge it.
  With leases, "gone quiet" is now visible on the board as a **stale** holder.
- **Rules-doc PRs** (`AGENTS.md`, `COORDINATION.md`, `FOCUS_AREAS.md`,
  `DECISIONS.md`) need **two peer reviews**, or an explicit self-review against the
  checklist in `docs/FOCUS_AREAS.md` §6.

## 7. The focus areas (data-driven)

The areas are the lock (full file map: `docs/FOCUS_AREAS.md` §2). The set is
**data**: `docs/focus-areas.json` lists the areas, their role codes, the process
roles, the channels, and the critical-path order; `scripts/coord` reads it and
falls back to built-in defaults if it is missing or broken. A **redesign** (add,
remove, split, rename) edits that file and `docs/FOCUS_AREAS.md`; it is a rules
change and should precede the initial agent request (docs/ORGANISATION.md §9).

|------|----------------|-----------------|
| Tactical / Mission | `focus: tactical` | `core/sim` mission, combat, weapons, objectives |
| Missions / Level Design | `focus: missions` | `assets/data/missions`, mission `.name`/`.desc` keys |

The fleet size **varies (1–10)**; the scheme does not care. With one agent, claim
any area. With ten, `scripts/coord status` shows the free ones and the fleet fans
out. Nobody assigns anything.

## 8. Why this is safe with unreliable agents

| Failure | What happens now |
|---------|------------------|
| An agent crashes mid-task | Its lease ages out in ≤ 24 h; the area frees itself. No peer or human has to notice. |
| An agent pauses for hours | Same: the TTL is the safety net. If it resumes before expiry, it renews. |
| Two agents race for one area | `git push --force-with-lease` is atomic: exactly one wins, the loser is told who holds it. |
| An agent forgets to release | The TTL reclaims it; a sweep deletes the ref. |
| An agent is unsure whether an area is free | `scripts/coord status` is authoritative; it is the ledger, not a comment. |
| Two agents both believe they own an area | They cannot: `coord check` fails CI on a collision, and the ledger has one ref per area. |
| A hand-written queue goes stale | There is no hand-written queue; the board is generated. |

## 9. Migration from the old comment protocol

If you are an agent that was already mid-cycle under the old `CLAIM:` comment
protocol, nothing is lost. See `docs/COORDINATION_MIGRATION.md`. In short:

```bash
scripts/coord migrate --issues <n> <n> ...     # import live legacy claims as leases
```

The tool still **reads** legacy `CLAIM:`/`LEASE:`/`TAKEOVER:` lines, so a claim
posted by a not-yet-updated agent is honoured during the transition.

### Transition to the hardened protocol (ADR-0025)

The 2026-10-15 hardening is **in place**, not a new protocol: the lease refs,
`claim` / `renew` / `release`, and the board format are unchanged, so an agent
that is mid-cycle **needs to do nothing** — its lease keeps working. Three things
change for a *working* agent, all non-destructive:

- **`stale` is display-only.** `STALE_AFTER` dropped from 12 h to 3 h, and to
  **2 h** in ADR-0037, so a quiet holder is flagged *before* its 6 h TTL expires. It never blocks `renew` or
  `release`, and `claim` still refuses to displace a **live** lease without
  `--takeover`, so no in-flight agent loses its area by surprise — a peer just
  *sees* that it may be gone and can take over deliberately.
- **A cross-area block is an issue, not a PR comment.** If your PR is blocked on
  another area, file the request as an issue labelled `focus: <that area>` (and
  add the area as a reviewer). A block posted only as a PR comment is invisible to
  the lane that must clear it. (The stalled content PR #235 case was re-filed as
  #294.) Already-open PRs are not retro-filed automatically — the block's owner
  re-files it when they next touch it.
- **A stray `status: claimed` may be cleared** by the sweep when no live lease
  backs it. The **lease is authoritative**, so if the label is dropped, `renew`
  restores it; a human question (`status: blocked` with no `blocked-by:` line) and
  a Rule 4 request (`status: needs-review`) are left alone.
- **A resolved block clears itself** (ADR-0030). A `status: blocked` issue whose
  body carries `blocked-by: #<n>` loses the label once every referenced issue is
  closed, so a dependent issue becomes claimable again without an agent editing
  it. Nothing to do while blocked; the label going away is the signal.

Nothing is lost: a live lease is never revoked by the transition, and the ledger
was already the source of truth.

## 10. What "good" looks like

- `main` is always green, and `coord check` is green.
- Every merge is traceable to an issue and an agent.
- Every area in flight has **exactly one** live lease; the board shows it.
- No agent waits on a missing one: an area whose holder is gone frees itself.
- Nobody hand-edits the board or opens a "refresh the queue" PR.
- A human question goes straight from the asking agent to the human — no relay.
- New agents read `AGENTS.md` + this page and are productive in one sitting.
