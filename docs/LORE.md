# Lore & Naming Guide

This document is the `focus: content` lane's reference for **names, wording, and
in-game text**. It exists so that every agent writes original FOSSynd text that
is consistent with the rest of the game and safe under `docs/LEGAL.md`.

It is a guide, not code. The authoritative rules for assets and names are
`docs/LEGAL.md`; where this file and `docs/LEGAL.md` disagree, `docs/LEGAL.md`
wins — then fix this file in the same change.

## 1. The one rule

**Write new text. Reuse nothing.** FOSSynd recreates the *mechanics* of
Syndicate (1993) and Syndicate Wars (1996); it must not copy their *expression*.
Concretely, never use, translate, or lightly respell any of these from the
originals:

- Faction, corporation, or organisation names.
- Character or agent names, or the names of any named individual.
- Weapon, gadget, or cybernetic names.
- Mission briefings, manual text, in-game messages, or marketing copy.
- The original product names as branding (`docs/LEGAL.md` hard rule 3). The
  project name is **FOSSynd**; keep "Syndicate" descriptive, never a brand mark.

If a name feels familiar from the original, **it is out of bounds**. Invent a new
one. "Inspired by the genre" is fine; "looks like the original's text" is not.

## 2. Voice and tone

The genre's flavour is corporate dystopia and dry, clinical menace. Match that
*feeling* with our own words:

- **Brief and imperative.** UI strings are commands and labels, not sentences.
- **Upper-case UI.** The bitmap font is ASCII 32–126; HUD strings are
  upper-case and terse (`OBJECTIVE: ELIMINATE ALL 6 ENEMY AGENTS`).
- **Neutral and bureaucratic.** The corporation speaks in the passive,
  cost-accounting register of a memo; it is unsettling because it is calm.
- **No humour that breaks the tone**, no modern slang, no brand references.

## 4. Writing strings (the string table)

UI text lives in `assets/lang/<lang>.json` and is read through
`core::i18n::StringTable` (ADR-0016). When you add or edit a string:

- **Key** = a stable dotted identifier, lower camel segments:
  `hud.objective.eliminate`, `title.controls.move`. Do not rename a key without
  an ADR — other areas compile against it.
- **Value** = the display text for that language. Keep the placeholder tokens the
  caller substitutes: `{count}`, `{x}`, `{y}`, `{seconds}`, `{version}`,
  `{marker}`, `{name}`, `{weapon}`, `{hp}`.
- **All upper-case for HUD/title text** (§2); sentence case is fine for future
  long-form text (briefings).
- **Never blank a value to "hide" a string.** `StringTable::get` returns the key
  when a lookup misses, so a blank value would show nothing — omit the key or
  give it real text instead.
- Add the same key to every language file you ship, or the fallback will show
  the key in that language.
- **ASCII only (32–126).** The embedded bitmap font (`src/game/Font.cpp`) has no
  accented glyphs, so transliterate rather than emit a character the renderer
  cannot draw (German ä/ö/ü → `AE`/`OE`/`UE`, ß → `SS`; see
  `assets/lang/de.json`). `tests/test_i18n.cpp` fails on a non-renderable value,
  so an unrenderable glyph cannot ship.

### 4a. Mission text keys

Mission-authored copy (a mission's `name` / `description` in
`assets/data/missions/*.json`) is localised through the same table (ADR-0020),
keyed by a **stable mission id** rather than the English display name:

- **Id** = the mission file stem (`assets/data/missions/demo.json` → `demo`), or
  an explicit `id` field once the content schema carries one.
- **Keys** = `mission.<id>.name` and `mission.<id>.desc`, resolved by
  `core::i18n::localizeMissionText`. The value is the mission's display copy in
  that language; the English value mirrors the mission file's own text.
- A mission with no keys, no id, or an empty value shows its authored text — so
  localisation is opt-in and never blanks a mission's copy.
- Sentence case is fine here (§2): these are briefings, not HUD chrome.
