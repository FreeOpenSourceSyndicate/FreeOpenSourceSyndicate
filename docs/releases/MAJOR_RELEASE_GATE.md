# Major-release gate — candidate + human approval

A **major version** (`X.0.0`) may not be rolled out until a **feature-complete
candidate** has been built, played by a **human**, and **approved**. This file is
the record of that gate. The rule is `AGENTS.md` §6a-i; the reasoning is
**ADR-0036**. Minor releases (`0.x.0`) do **not** use this file — they follow
`AGENTS.md` §6a as before.

Everything here is filled in **per candidate** (one section per `-rc.N`). Agents
prepare the candidate and the checklist; a **human supplies the approval**. An
agent must **never self-approve** a major version.

The first major version is **v1.0.0**. Its Definition of Done is `docs/ROADMAP.md`
→ *Definition of Done — v1.0.0* and `AGENTS.md` §9. **It is not candidate-able
yet** — Milestone C still has open items (see the bottom of this file).

---

## How to use this file

1. An agent, when the Definition of Done is fully met, cuts the candidate branch
   and a **pre-release** tag (`vX.Y.Z-rc.N`) and fills in the checklist below.
2. The human builds the candidate **from that exact branch/tag**, following the
   candidate's `docs/releases/vX.Y.Z-<slug>.md`, and plays it.
3. The human records the verdict in the **Approval** block. Only an approval
   unblocks the final `vX.Y.Z` tag and the rollout (§6a-i).

If the playtest finds gaps, **do not re-tag the candidate** (§6b): fix on `main`,
cut `-rc.N+1`, and fill in a new section.
