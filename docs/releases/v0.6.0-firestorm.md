# v0.6.0 — "Firestorm"

**Release date:** 2026-10-15 · **Branch:** `release/v0.6.0-firestorm` · **Tag:** `v0.6.0`

These instructions are **specific to this release**. If you are building `main`
or another version, use [`docs/BUILD.md`](../BUILD.md) instead.

## What is new in this version (visible difference)

A playtester who has seen v0.5.0 should notice these:

1. **Walls now block sight and fire.** Enemies no longer see or shoot through a
   wall, and neither do you: cover matters, and a corridor changes the fight.
2. **New weapons with real punch.** The catalogue gained an explosive **launcher**
   (damage in a radius, not just the target) plus a **minigun**, **flamethrower**,
   and **laser** — each a distinct niche — so missions can field a much wider
   range of firepower.
3. **Smoother squad control.** **Drag a rectangle** to box-select a group
   (shift-drag adds); **shift-click** appends a waypoint to each selected agent's
   route, which is now **drawn on screen** as a numbered path; the squad walks
   diagonally across open ground instead of staircasing; and a blocked move
   order now walks the agent as close as it can instead of being dropped.
4. **Recruit and heal.** Press **`P`** to turn a bystander into a follower
   (Compliance Beacon), **`F`** to release them, and a **medikit** gadget can heal
   a wounded ally (engine + tests; see the note below).
5. **A real package, and a German UI.** `cpack` produces a Linux **`.tar.gz`**
   and **`.deb`** and (on macOS) a **`.dmg`**; `--lang de` loads a complete German
   translation. The CLI can now describe itself with **`--version`** and
   **`--help`**, and **`--window WxH`** sets the window size.
6. **The version reads `v0.6.0`** (codename **`FIRESTORM`**) in the window title,
   the HUD, and the title card, so you can confirm at a glance which build you
   are running.

## What you need

- A Debian-based Linux machine (Mint, Ubuntu, Debian) — the primary, tested
  platform.
- `git`, a C++17 compiler, `cmake` (>= 3.15), and `libsdl2-dev`.
- No GPU and no external assets are required: the game draws itself and embeds
  its own font, its demo mission, its sprite sheet, and its string tables.

## 3. Install a runnable copy (recommended)

The game is a single self-contained executable, but its missions, catalogues,
and locales are also shipped as data so they can be edited without rebuilding.
`cmake --install` puts them in the standard places:

```bash
sudo cmake --install build --prefix /usr/local
# -> /usr/local/bin/FOSSynd
# -> /usr/local/share/fossynd/missions/*.json      (demo + escort)
# -> /usr/local/share/fossynd/weapons.json, agents.json
# -> /usr/local/share/fossynd/lang/*.json          (en + de)
# -> /usr/local/share/fossynd/fossynd.conf.example
```

Run it from anywhere:

```bash
FOSSynd
```

It finds its mission via the built-in fallback search (`/usr/local/share`,
`/usr/share`, next to the binary, repo-relative) and falls back to the embedded
copy if none is found — so it still runs if you only copy the binary.

### Or build a package

```bash
cmake -S . -B build -DFOSSYND_BUILD_GAME=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build -j"$(nproc)"
(cd build && cpack)      # -> FOSSynd-0.6.0-Linux.tar.gz  and  fossynd_0.6.0_amd64.deb
```

## 4. Copy a runnable copy to another computer

There are two ways. Pick whichever suits the target machine.

### Option A — copy just the binary (simplest)

The binary embeds the font, the demo mission, the sprite sheet, and the string
tables, so it runs alone. SDL2 must be present on the target.

```bash
mkdir -p foss-v0.6.0
cp build/src/FOSSynd-0.6.0 foss-v0.6.0/   # the real file
cp build/src/FOSSynd        foss-v0.6.0/   # the symlink (optional)
scp -r foss-v0.6.0 user@other-host:/home/user/     # or: cp -r foss-v0.6.0 /media/$USER/USBSTICK/
```

On the target machine:

```bash
sudo apt-get install -y libsdl2-2.0-0
cd /home/user/foss-v0.6.0
chmod +x FOSSynd-0.6.0
./FOSSynd-0.6.0
```

### Option B — copy an installed tree (keeps the missions and locales editable)

Install into a staging prefix, then copy the whole tree, preserving the relative
layout so the fallback search finds the data:


On the target machine:

```bash

```

### Option C — copy the package

Copy `FOSSynd-0.6.0-Linux.tar.gz` (or the `.deb`) to the target and unpack or
install it there:

```bash

```

> If the binary is for a different architecture, or the target has a much older

## 5. Controls

- **Left-click** — move the squad (or select an agent under the cursor).
- **Left-drag** — box-select every agent inside the rectangle (shift-drag adds).
- **Shift + click** — append a waypoint to the selection's route (drawn on screen).
- **Keys `1`–`4`** — recall control group 1–4; **Ctrl + `1`–`4`** assign it.
  **`5`–`8`** select the 1st–4th living agent. **`A`** selects all.
- **Right-click** (or click) an enemy — order the selection to attack it.
- **`P`** — persuade the nearest civilian with the selection (recruit a follower).
- **`F`** — release the followers of the selected agents.
- **Arrow keys** — scroll the camera. **`R`** — restart. **`Esc`** — quit.
- **`--demo`** — attract mode: the squad fights on its own.

> The **medikit** and the **area-effect weapons** exist in the simulation and are
> covered by tests, but no key is bound to the medikit yet; the `launcher` and
> the new weapon tier are used by mission/agent data rather than a HUD control.
