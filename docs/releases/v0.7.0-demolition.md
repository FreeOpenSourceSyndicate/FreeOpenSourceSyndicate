# v0.7.0 — "Demolition"

**Release date:** 2026-10-15 · **Branch:** `release/v0.7.0-demolition` · **Tag:** `v0.7.0`

These instructions are **specific to this release**. If you are building `main`
or another version, use [`docs/BUILD.md`](../BUILD.md) instead.

## What is new in this version (visible difference)

A playtester who has seen v0.6.0 should notice these:

1. **The map has real artwork.** The floor and walls are no longer flat colour
   diamonds: each cell is drawn from an authored pixel-art isometric tile — a
   light/dark checkerboard floor, a raised wall, and a **cracked** wall — so the
   board reads as a place, not a grid.
2. **Walls can be destroyed.** Shoot a **cracked** wall and it takes damage; when
   it breaks it opens up (walkable), so a blocked corridor becomes a route. Solid
   walls still just absorb the round. Enemies also **break for cover** when you
   shoot at them, so you have to flank rather than out-shoot them.
3. **The view zooms and goes fullscreen.** Zoom in whole steps (**1x/2x/3x**) with
   **`+`**/**`-`** or the **mouse wheel**; toggle **fullscreen** with **`F11`**.
   Both keep the chunky pixel look (nearest-neighbour) and the mouse still picks
   and orders correctly at every zoom.
4. **Pause when you need to.** Press **`Space`** to freeze the simulation; a
   centred **`PAUSED`** band appears. Press **`Space`** again to resume.
5. **The mission name is localised and on screen.** The current mission's name is
   shown in the **HUD top bar** and the **window title**, in the active language
   (`--lang de` gives the German name), not just in the file.
6. **A shield gadget, and cleaner content.** The simulation gained a **shield**
   that absorbs the next hit (engine + tests; no key bound yet), and the content
   loader now **rejects off-map geometry** and out-of-range weapon values instead
   of silently ignoring them.
7. **The version reads `v0.7.0`** (codename **`DEMOLITION`**) in the window title,
   the HUD, and the title card, so you can confirm at a glance which build you
   are running.

## What you need

- A Debian-based Linux machine (Mint, Ubuntu, Debian) — the primary, tested
  platform.
- `git`, a C++17 compiler, `cmake` (>= 3.15), and `libsdl2-dev`.
- No GPU and no external assets are required: the game draws itself and embeds
  its own font, its demo mission, its sprite and tile sheets, and its string
  tables.

## 3. Install a runnable copy (recommended)

The game is a single self-contained executable, but its missions, catalogues,
and locales are also shipped as data so they can be edited without rebuilding.
`cmake --install` puts them in the standard places:

```bash
sudo cmake --install build --prefix /usr/local
# -> /usr/local/bin/FOSSynd
# -> /usr/local/share/fossynd/missions/*.json      (demo + escort)
# -> /usr/local/share/fossynd/weapons.json, agents.json
# -> /usr/local/share/fossynd/lang/*.json          (en + de)
# -> /usr/local/share/fossynd/fossynd.conf.example
```

Run it from anywhere:

```bash
FOSSynd
```

It finds its mission via the built-in fallback search (`/usr/local/share`,
`/usr/share`, next to the binary, repo-relative) and falls back to the embedded
copy if none is found — so it still runs if you only copy the binary.

### Or build a package

```bash
cmake -S . -B build -DFOSSYND_BUILD_GAME=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build -j"$(nproc)"
(cd build && cpack)      # -> FOSSynd-0.7.0-Linux.tar.gz  and  fossynd_0.7.0_amd64.deb
```

## 4. Copy a runnable copy to another computer

There are two ways. Pick whichever suits the target machine.

### Option A — copy just the binary (simplest)

The binary embeds the font, the demo mission, the sprite and tile sheets, and the
string tables, so it runs alone. SDL2 must be present on the target.

```bash
mkdir -p foss-v0.7.0
cp build/src/FOSSynd-0.7.0 foss-v0.7.0/   # the real file
cp build/src/FOSSynd        foss-v0.7.0/   # the symlink (optional)
scp -r foss-v0.7.0 user@other-host:/home/user/     # or: cp -r foss-v0.7.0 /media/$USER/USBSTICK/
```

On the target machine:

```bash
sudo apt-get install -y libsdl2-2.0-0
cd /home/user/foss-v0.7.0
chmod +x FOSSynd-0.7.0
./FOSSynd-0.7.0
```

### Option B — copy an installed tree (keeps the missions and locales editable)

Install into a staging prefix, then copy the whole tree, preserving the relative
layout so the fallback search finds the data:

```bash
cmake --install build --prefix /tmp/foss-stage
scp -r /tmp/foss-stage user@other-host:/home/user/foss-v0.7.0
```

On the target machine:

```bash
sudo apt-get install -y libsdl2-2.0-0
/home/user/foss-v0.7.0/bin/FOSSynd
```

### Option C — copy the package

Copy `FOSSynd-0.7.0-Linux.tar.gz` (or the `.deb`) to the target and unpack or
install it there:

```bash
tar xzf FOSSynd-0.7.0-Linux.tar.gz       # or: sudo dpkg -i fossynd_0.7.0_amd64.deb
```

> If the binary is for a different architecture, or the target has a much older
> libc than the build machine, build it on the target instead (step 2). The
> source and the build are tiny, so building in place is always an option.

## 5. Controls

- **Left-click** — move the squad (or select an agent under the cursor).
- **Left-drag** — box-select every agent inside the rectangle (shift-drag adds).
- **Shift + click** — append a waypoint to the selection's route (drawn on screen).
- **Keys `1`–`4`** — recall control group 1–4; **Ctrl + `1`–`4`** assign it.
  **`5`–`8`** select the 1st–4th living agent. **`A`** selects all.
- **Right-click** (or click) an enemy — order the selection to attack it.
- **`P`** — persuade the nearest civilian with the selection (recruit a follower).
- **`F`** — release the followers of the selected agents.
- **`+` / `-` or the mouse wheel** — zoom the view (1x/2x/3x, nearest-neighbour).
- **`F11`** — toggle fullscreen.
- **`Space`** — pause / resume the simulation.
- **Arrow keys** — scroll the camera. **`R`** — restart. **`Esc`** — quit.
- **`--demo`** — attract mode: the squad fights on its own.

> The **shield**, the **medikit**, and the **area-effect weapons** exist in the
> simulation and are covered by tests, but no key is bound to the shield or the
> medikit yet; the `launcher` and the weapon tiers are used by mission/agent data
> rather than a HUD control.
