# v0.8.0 — "Dominion"

**Release date:** 2026-10-16 · **Branch:** `release/v0.8.0-dominion` · **Tag:** `v0.8.0`

These instructions are **specific to this release**. If you are building `main`
or another version, use [`docs/BUILD.md`](../BUILD.md) instead.

## What is new in this version (visible difference)

A playtester who has seen v0.7.0 should notice these:

1. **There is a war map above the battlefield.** Press **`M`** (or start with
   `--map`) and the tactical board gives way to a **world-map management screen**:
   a graph of **territories**, each owned by you, a rival, or nobody. This is the
   metagame — the whole point of this release.
2. **You can tax, research, buy, and deploy.** Click a territory you own and
   press **`-`**/**`+`** to set its **tax**; income accrues to your **FUNDS** over
   time. Press **`B`** to open the **R&D shop** — fund research nodes and buy
   equipment (weapons, gadgets, cybernetics) into a four-slot **loadout** — and
   press **`D`** on a reachable territory to **deploy**: the map's mission loads
   on the tactical board with the squad you *bought*.
3. **The loop closes.** Win the deployed mission and the territory is **yours**;
   lose and you do not take it. Take **every** territory and a centred
   **`CAMPAIGN WON`** panel appears; if the syndicate is wiped out you get
   **`CAMPAIGN LOST`**. Either way the map **freezes** — the end state is final.
4. **You buy your squad, and the gear reaches it.** Territories pay **income**,
   **research** unlocks better gear over time, and **purchased equipment** deploys
   with you. Over-tax a territory and it **revolts** back to neutral. Bought
   **cybernetic upgrades** permanently change your agents' stats at mission load
   (faster legs, steadier aim, more health, longer sight).
5. **The gadgets are bound to keys, and the objective set is complete.** Use a
   **medikit** (**`H`**), a **shield** (**`S`**), a **scanner** (**`C`**) that
   marks enemies in a radius (drawn as a ring plus a crosshair on each revealed
   enemy, and on the minimap), and **performance drugs** (**`B`**) for a timed
   speed/hit buff — each on the current selection. Missions can now be
   **escort**, **destroy**, or **persuade**, not just eliminate/reach/survive.
6. **Breached walls read as rubble.** A wall you shoot open is drawn as **rubble**
   instead of a plain floor tile, so your breach is visible on the board.
7. **The version reads `v0.8.0`** (codename **`DOMINION`**) in the window title,
   the HUD, and the title card, so you can confirm at a glance which build you
   are running.
8. **Map-screen keys stay on the map.** Tactical hotkeys (the gadget keys, pause,
   restart) no longer leak through to the board while the management screen is
   open, so managing the war map can no longer fire a medikit or restart the
   mission behind it.

## What you need

- A Debian-based Linux machine (Mint, Ubuntu, Debian) — the primary, tested
  platform.
- `git`, a C++17 compiler, `cmake` (>= 3.15), and `libsdl2-dev`.
- No GPU and no external assets are required: the game draws itself and embeds
  its own font, its missions, its sprite and tile sheets, and its string tables.

## 2. Build and play (standard)

```bash
sudo apt-get update
sudo apt-get install -y build-essential cmake git libsdl2-dev

cmake -S . -B build -DFOSSYND_BUILD_GAME=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build -j"$(nproc)"

./build/src/FOSSynd          # play (title card -> mission)
./build/src/FOSSynd --map    # start on the campaign management screen
./build/src/FOSSynd --demo   # hands-off attract mode (skips the title card)
./build/src/FOSSynd --help   # list every flag
./build/src/FOSSynd --version
ctest --test-dir build --output-on-failure   # should report 51/51 tests passed
```

### The campaign screen

While the management screen is up, the tactical simulation is frozen and the
campaign clock ticks instead:

- **`M`** — toggle between the tactical board and the world map.
- **Click** a territory to select it (its name, owner, mission, tax, and status
  show in the sidebar).
- **`-`** / **`+`** — lower / raise the selected territory's tax.
- **`B`** — open the **R&D shop**: **Up/Down** move through the research tree and
  the equipment catalogue, **Left/Right** pick the squad slot, and **Enter**
  funds a research node or buys and assigns the selected gear. **`Esc`**/`B`
  closes it.
- **`D`** — deploy the selected territory's mission (starts the tactical board
  with your bought loadout).
- **`Esc`** — quit.

## 3. Install a runnable copy (recommended)

The game is a single self-contained executable, but its missions, catalogues,
locales, and **metagame world data** are also shipped as data so they can be
edited without rebuilding. `cmake --install` puts them in the standard places:

```bash
sudo cmake --install build --prefix /usr/local
# -> /usr/local/bin/FOSSynd
# -> /usr/local/share/fossynd/missions/*.json      (demo + escort)
# -> /usr/local/share/fossynd/world/*.json         (campaign, world, research, equipment)
# -> /usr/local/share/fossynd/weapons.json, agents.json, vehicles.json
# -> /usr/local/share/fossynd/lang/*.json          (en + de)
# -> /usr/local/share/fossynd/fossynd.conf.example
```

Run it from anywhere:

```bash
FOSSynd
```

It finds its mission and campaign via the built-in fallback search
(`/usr/local/share`, `/usr/share`, next to the binary, repo-relative) and falls
back to the embedded copy if none is found — so it still runs if you only copy
the binary.

### Or build a package

```bash
cmake -S . -B build -DFOSSYND_BUILD_GAME=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build -j"$(nproc)"
(cd build && cpack)      # -> FOSSynd-0.8.0-Linux.tar.gz  and  fossynd_0.8.0_amd64.deb
```

## 4. Copy a runnable copy to another computer

There are two ways. Pick whichever suits the target machine.

### Option A — copy just the binary (simplest)

The binary embeds the font, the missions, the sprite and tile sheets, and the
string tables, so it runs alone. SDL2 must be present on the target.

```bash
mkdir -p foss-v0.8.0
cp build/src/FOSSynd-0.8.0 foss-v0.8.0/   # the real file
cp build/src/FOSSynd        foss-v0.8.0/   # the symlink (optional)
scp -r foss-v0.8.0 user@other-host:/home/user/     # or: cp -r foss-v0.8.0 /media/$USER/USBSTICK/
```

On the target machine:

```bash
sudo apt-get install -y libsdl2-2.0-0
cd /home/user/foss-v0.8.0
chmod +x FOSSynd-0.8.0
./FOSSynd-0.8.0
```

> To reach the **campaign**, the target needs the `world/*.json` data too — see
> Option B. The tactical game runs from the binary alone.

### Option B — copy an installed tree (keeps the missions, world, and locales editable)

```bash
scp -r /tmp/foss-stage user@other-host:/home/user/foss-v0.8.0
```

On the target machine:

```bash

```

### Option C — copy the package

Copy `FOSSynd-0.8.0-Linux.tar.gz` (or the `.deb`) to the target and unpack or
install it there:

## 5. Controls

### Tactical board

- **Left-click** — move the squad (or select an agent under the cursor).
- **Left-drag** — box-select every agent inside the rectangle (shift-drag adds).
- **Shift + click** — append a waypoint to the selection's route (drawn on screen).
- **Keys `1`–`4`** — recall control group 1–4; **Ctrl + `1`–`4`** assign it.
  **`5`–`8`** select the 1st–4th living agent. **`A`** selects all.
- **Right-click** (or click) an enemy — order the selection to attack it.
- **`P`** — persuade the nearest civilian with the selection (recruit a follower).
- **`F`** — release the followers of the selected agents.
- **`H`** / **`S`** / **`C`** / **`B`** — use a **medikit** / raise a **shield** /
  run a **scanner** pulse / take **performance drugs** on the selection.
- **`+` / `-` or the mouse wheel** — zoom the view (1x/2x/3x, nearest-neighbour).
- **`F11`** — toggle fullscreen.
- **`Space`** — pause / resume the simulation.
- **`M`** — open the campaign management screen.
- **Arrow keys** — scroll the camera. **`R`** — restart. **`Esc`** — quit.
- **`--demo`** — attract mode: the squad fights on its own.

### Campaign management screen

- **Click** a territory to select it; **`-`**/**`+`** change its tax; **`B`** opens
  the R&D shop; **`D`** deploys; **`M`** returns to the tactical board; **`Esc`**
  quits.

> The **shield**, **medikit**, **scanner**, and **performance drugs** are bound
> to **`S`**, **`H`**, **`C`**, and **`B`** on the tactical board, and also reach

## Known limitations in v0.8.0

- The **campaign screen** is keyboard/mouse only and there is **no save/load**:
  a campaign lasts for one session.
- The map screen's territory **layout is view-only** (a deterministic BFS ring,
  never saved) and the **minimap** in the tactical view is display-only.
- The **shield**, **medikit**, **scanner**, and **performance drugs** are bound
  to **`S`/`H`/`C`/`B`** on the tactical board and reach a mission through a
  bought loadout in the R&D shop.
- **Vehicles** (`core::Vehicle`) are modelled, `Mission` owns their policy
  (hijack, drive, mounted fire — ADR-0032), and the view **draws** them (a live
  vehicle and its wreck, `--vehicle`/`--check-vehicles`, #366). What is still
  missing is the **player key path**: there is no hotkey to hijack or drive one,
  and no shipped mission places a vehicle, so in play they appear only where a
  mission spawns them.
- Only **two missions** ship (the demo and "Rooftop Exfil"); the campaign reuses
  them across territories until Tactical authors more.
- The macOS package lane is best-effort (macOS CI runners are limited); Linux is
  the hard-gated platform.
