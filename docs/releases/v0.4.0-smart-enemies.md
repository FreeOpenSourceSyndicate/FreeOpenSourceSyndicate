**Release date:** 2026-10-13 · **Branch:** `release/v0.4.0-smart-enemies` · **Tag:** `v0.4.0`

## What is new in this version (visible difference)

A playtester who has seen v0.3.0 should notice these immediately:

1. **A pixel-art title card.** Launching the game now opens on an authored,
   chunky pixel-art screen showing the name, the version, and the controls.
   Press any key (or click) to start; it also starts itself after a few seconds.
2. **Enemies are smarter.** They no longer charge blindly. With nothing in
   sight they walk a patrol route; once they see your squad they engage; and
   when badly wounded they **break off and retreat**. The first time one engages
   it **calls nearby allies** onto your squad.
3. **The project is now called FOSSynd.** The window title, the HUD, and the
   title card all read `FOSSynd`, and the version reads `v0.4.0`, so you can
   confirm at a glance which build you are running.
4. **A real install layout.** `cmake --install` now installs the binary *and* its
   mission data and example config, so an installed copy finds its content
   without you telling it where to look (see below).
5. **An authored pixel-art release banner** (`assets/ui/banner.png`, generated
   from `assets/ui/make_banner.py`) for the release page.

## What you need

- A Debian-based Linux machine (Mint, Ubuntu, Debian) — the primary, tested
  platform.
- `git`, a C++17 compiler, `cmake` (>= 3.15), and `libsdl2-dev`.
- No GPU and no external assets are required: the game draws itself and embeds
  its own font and the demo mission.

## 2. Build and play (standard)

```bash
sudo apt-get update
sudo apt-get install -y build-essential cmake git libsdl2-dev

cmake -S . -B build -DFOSSYND_BUILD_GAME=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build -j"$(nproc)"

./build/src/FOSSynd          # play (title card -> mission)
./build/src/FOSSynd --demo   # hands-off attract mode (skips the title card)
ctest --test-dir build --output-on-failure   # should report 5/5 tests passed
```

### Old hardware (low-spec)

```bash
cmake -S . -B build -DFOSSYND_BUILD_GAME=ON -DFOSSYND_LOW_SPEC=ON -DCMAKE_BUILD_TYPE=Release

./build/src/FOSSynd          # 320x200 window, software renderer
```

You can also run any build in low-spec mode at runtime with `--low-spec`.

## 3. Install a runnable copy (recommended)

The game is a single self-contained executable, but the mission is also shipped
as data so it can be edited without rebuilding. `cmake --install` puts both in
the standard places:

```bash
sudo cmake --install build --prefix /usr/local
# -> /usr/local/bin/FOSSynd
# -> /usr/local/share/fossynd/missions/demo.json
# -> /usr/local/share/fossynd/fossynd.conf.example
```

Run it from anywhere:

```bash
FOSSynd
```

It finds its mission via the built-in fallback search (`/usr/local/share`,
`/usr/share`, next to the binary, repo-relative) and falls back to the embedded
copy if none is found — so it still runs if you only copy the binary.

## 4. Copy a runnable copy to another computer

There are two ways. Pick whichever suits the target machine.

### Option A — copy just the binary (simplest)

The binary embeds the font and the demo mission, so it runs alone. SDL2 must be
present on the target.

```bash
mkdir -p foss-v0.4.0
cp build/src/FOSSynd-0.4.0 foss-v0.4.0/   # the real file
cp build/src/FOSSynd        foss-v0.4.0/   # the symlink (optional)
scp -r foss-v0.4.0 user@other-host:/home/user/     # or: cp -r foss-v0.4.0 /media/$USER/USBSTICK/
```

On the target machine:

```bash
sudo apt-get install -y libsdl2-2.0-0
cd /home/user/foss-v0.4.0
chmod +x FOSSynd-0.4.0
./FOSSynd-0.4.0
```

### Option B — copy an installed tree (keeps the mission editable)

Install into a staging prefix, then copy the whole tree, preserving the relative
layout so the fallback search finds the data:

```bash
cmake --install build --prefix /tmp/foss-stage
scp -r /tmp/foss-stage user@other-host:/home/user/foss-v0.4.0
```

On the target machine:

```bash
sudo apt-get install -y libsdl2-2.0-0
/home/user/foss-v0.4.0/bin/FOSSynd
```

> If the binary is for a different architecture, or the target has a much older
> libc than the build machine, build it on the target instead (step 2). The
> source and the build are tiny, so building in place is always an option.

## 5. Controls

- **Left-click** — move the squad (or select an agent under the cursor).
- **Shift + click**, keys **1**–**4**, **A** — select individual agents / all.
- **Right-click** (or click) an enemy — order the selection to attack it.
- **Arrow keys** — scroll the camera. **R** — restart. **Esc** — quit.
- **`--demo`** — attract mode: the squad fights on its own.
