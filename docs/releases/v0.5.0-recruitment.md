# v0.5.0 — "Recruitment"

**Release date:** 2026-10-14 · **Branch:** `release/v0.5.0-recruitment` · **Tag:** `v0.5.0`

These instructions are **specific to this release**. If you are building `main`
or another version, use [`docs/BUILD.md`](../BUILD.md) instead.

## What is new in this version (visible difference)

A playtester who has seen v0.4.0 should notice these immediately:

1. **Agents are real pixel-art sprites.** The flat coloured diamonds are gone.
   Your squad, the enemy guards, and the civilians are now authored pixel-art
   sprites with a short walk cycle, drawn depth-sorted against crates and
   barrels on the map.
2. **You can recruit bystanders.** Press **`P`** with an agent selected to use the
   *Compliance Beacon*: the nearest civilian becomes a **follower** (rendered cyan)
   that trails your squad. Press **`F`** to release the followers of the
   selection. The HUD shows a `FOLLOWERS` count once you have any.
3. **A minimap shows the whole board.** A panel in the top-right corner gives a
   whole-board overview: the static terrain plus a live blip for every living
   agent (your squad green, enemies red, civilians pale, followers cyan; selected
   agents highlighted), so you can see the fight without scrolling.
4. **Missions can set their own objective.** Besides "eliminate all enemies", a
   mission can now ask you to **reach a tile** or **survive** for a time; the HUD
   names the active objective. A new sample mission ("Rooftop Exfil") uses a
   `reach` objective.
5. **The version reads `v0.5.0`** in the window title, the HUD, and the title
   card, so you can confirm at a glance which build you are running.
6. **An authored pixel-art release banner** (`assets/ui/banner.png`, generated
   from `assets/ui/make_banner.py`) for the release page.

## What you need

- A Debian-based Linux machine (Mint, Ubuntu, Debian) — the primary, tested
  platform.
- `git`, a C++17 compiler, `cmake` (>= 3.15), and `libsdl2-dev`.
- No GPU and no external assets are required: the game draws itself and embeds
  its own font, its demo mission, and its sprite sheet.

```bash

cmake -S . -B build -DFOSSYND_BUILD_GAME=ON -DCMAKE_BUILD_TYPE=Release
```

## 3. Install a runnable copy (recommended)

The game is a single self-contained executable, but its missions are also shipped
as data so they can be edited without rebuilding. `cmake --install` puts both in
the standard places:

```bash
sudo cmake --install build --prefix /usr/local
# -> /usr/local/bin/FOSSynd
# -> /usr/local/share/fossynd/missions/demo.json
# -> /usr/local/share/fossynd/fossynd.conf.example
```

Run it from anywhere:

```bash
FOSSynd
```

It finds its mission via the built-in fallback search (`/usr/local/share`,
`/usr/share`, next to the binary, repo-relative) and falls back to the embedded
copy if none is found — so it still runs if you only copy the binary.

## 4. Copy a runnable copy to another computer

There are two ways. Pick whichever suits the target machine.

### Option A — copy just the binary (simplest)

The binary embeds the font, the demo mission, and the sprite sheet, so it runs
alone. SDL2 must be present on the target.

```bash
mkdir -p foss-v0.5.0
cp build/src/FOSSynd-0.5.0 foss-v0.5.0/   # the real file
cp build/src/FOSSynd        foss-v0.5.0/   # the symlink (optional)
scp -r foss-v0.5.0 user@other-host:/home/user/     # or: cp -r foss-v0.5.0 /media/$USER/USBSTICK/
```

On the target machine:

```bash
sudo apt-get install -y libsdl2-2.0-0
cd /home/user/foss-v0.5.0
chmod +x FOSSynd-0.5.0
./FOSSynd-0.5.0
```

### Option B — copy an installed tree (keeps the demo mission editable)

Install into a staging prefix, then copy the whole tree, preserving the relative
layout so the fallback search finds the data:

```bash
cmake --install build --prefix /tmp/foss-stage
scp -r /tmp/foss-stage user@other-host:/home/user/foss-v0.5.0
```

On the target machine:

```bash
sudo apt-get install -y libsdl2-2.0-0
/home/user/foss-v0.5.0/bin/FOSSynd
```

> If the binary is for a different architecture, or the target has a much older
> libc than the build machine, build it on the target instead (step 2). The
> source and the build are tiny, so building in place is always an option.

## 5. Controls

- **Left-click** — move the squad (or select an agent under the cursor).
- **Shift + click**, keys **1**–**4**, **A** — select individual agents / all.
- **Right-click** (or click) an enemy — order the selection to attack it.
- **`P`** — persuade the nearest civilian with the selection (recruit a follower).
- **`F`** — release the followers of the selected agents.
- **Arrow keys** — scroll the camera. **R** — restart. **Esc** — quit.
- **`--demo`** — attract mode: the squad fights on its own.

## Known limitations in v0.5.0

- There is still **no zoom**; the minimap is display-only (you cannot click it
  to move the camera).
- Rendering does not yet interpolate between fixed simulation steps (the core
  timing pieces exist; the view will consume them in a later release).
- Two missions ship (the demo and "Rooftop Exfil"); still no metagame,
  cybernetics, or vehicles.
- Followers trail their leader but have no independent orders yet.
