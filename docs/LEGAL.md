# Legal & Copyright Policy

This project recreates the **gameplay** of Syndicate (1993, Bullfrog
Productions / Electronic Arts) and Syndicate Wars (1996). Game *mechanics* and
*ideas* are generally not protected by copyright; specific *expression* is. We
stay on the safe side of that line.

> This is engineering guidance, not legal advice. If a question is unclear,
> open an issue labeled `question` and involve a human maintainer before
> proceeding.

## Hard rules — never do these

1. **No original assets.** Do not use, rip, trace, convert, or re-render any
   sprite, tile, texture, font, sound effect, music track, or video from the
   original games or their marketing.
2. **No original code.** Do not decompile, copy, or transcribe original engine
   or game code. Everything here is written from scratch.
3. **No trademarks as branding.** "Syndicate" and "Syndicate Wars" are
   trademarks of their owners. Do not use them as the product name, logo, or in
   a way that implies affiliation. The project name **FOSSynd** (Free,
   Open-Source Syndicate) is our own; keep "Syndicate" descriptive, not as a
   brand mark.
4. **No verbatim text.** Do not copy mission briefings, manuals, in-game text,
   names of characters/factions/companies, or marketing copy from the originals.
   Write new lore.
5. **No extracted data.** Do not import original level files, tile sets,
   balance tables, or text dumps.

## What we *may* do

- Implement generic mechanics: isometric rendering, squad control, pathfinding,
  hit chance, research trees, territory income. These are common to many games.
- Use the genre's common vocabulary in **new, original** content.
- Study the original game's *behaviour* (from memory / public descriptions) and
  reimplement the *rules* in our own way.

## Naming and lore

- Factions, corporations, characters, weapons, and gadgets must be **new
  names**. If a name is memorable from the original, do not reuse it.
- Keep a distinct visual identity. Aim for "inspired by", not "looks identical".
- **Before naming a new gadget/weapon/faction**, take the name from the
  `focus: text` lexicon in `docs/LORE.md` §3, or propose a new entry there. If a
  name would echo the original, it needs an ADR (`docs/DECISIONS.md`) before it
  lands — see ADR-0018, which renamed the recruiter gadget off the original's
  name.

## Assets

Every asset must be either original (created for this project) or carry an
explicit license compatible with MIT (e.g. CC0, CC-BY). See `docs/ASSETS.md`
for the registry and provenance requirements.

## Provenance for AI-generated assets

AI-generated images/audio are allowed **only if** the generating tool's terms
permit commercial use and the output is not itself derivative of copyrighted
material. Record the tool and prompt in `docs/ASSETS.md`. When in doubt, leave
it out.

## Code provenance

- Do not paste code from Stack Overflow, blogs, or other repos unless the
  license is MIT-compatible **and** you add attribution in `NOTICE`/`LICENSE`
  and the file header.
- GPL/AGPL code must not be introduced into this MIT project.

## Reporting

If you believe content in this repo infringes a right, open an issue labeled
`question` or contact a maintainer. We will remove disputed content promptly.
