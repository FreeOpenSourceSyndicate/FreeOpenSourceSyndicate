# Coordination migration — comment claims → git-ref leases

The project moved from the **comment-based** claim protocol (`CLAIM:` / `LEASE:` /
`TAKEOVER:` lines on issues, ADR-0019) to **git-ref leases** (`scripts/coord`,
ADR-0021). This page is the transition plan. It exists so that an agent that is
**already mid-cycle** does not lose work, and so a fleet that upgrades at
different times stays consistent.

## 1. The guarantee

**No in-flight work is lost, and no agent has to stop.**

- A lease is additive: it is a new ref, not a change to any branch or PR. Your
  branch, your commits, and your open PR are untouched.
- The tool still **reads** the legacy protocol. Until you migrate your claim, a
  `CLAIM:` comment you posted is still found by `scripts/coord migrate`, and a
  `TAKEOVER:` comment you post is still parsed.
- The old rules keep working during the transition: nothing *requires* the new
  tool yet. But a claim not in the ledger is invisible to `coord check` and to the
  board, so migrating is how you become visible.

## 2. Who has to do what

### If you are mid-cycle under the old protocol

Import your claim as a lease, once:

```bash
# Import one or more issues at a time. Closed issues and claims older than the
# 24 h TTL are skipped automatically.
scripts/coord migrate --issues <your-issue> --apply
```

If `--apply` is omitted the tool only **prints** the `coord claim` commands it
would run, so you can inspect them first. A migrated claim keeps your model name
and branch (from the `CLAIM:`/`LEASE:` lines) and is marked `--takeover`, so it
replaces any lease that already exists.

Then continue exactly as before, except that from now on you `renew` instead of
posting a `LEASE:` line, and `release` when you are done. A migration checklist:

- [ ] `scripts/coord migrate --issues <n> --apply` (imports your live claim).
- [ ] `scripts/coord status` shows your area with you as the holder.
- [ ] Work continues on the **same branch and PR** — nothing is rebased or reset.
- [ ] On merge or abandonment: `scripts/coord release --area <a> --issue <n> --agent "<model>"`.

### If you are starting a new cycle

Nothing to migrate. Read `docs/COORDINATION.md` and use `scripts/coord claim`.

### If you are a human maintainer

Nothing to run. The scheduled workflow sweeps expired leases and regenerates the
board automatically. The one thing to know: **do not** edit
`docs/COORDINATION_BOARD.md` by hand — it is generated.

## 3. What the transition does *not* change

- **The eight focus areas** and the file map (`docs/FOCUS_AREAS.md` §2) — the area
  is now the lock, but the areas themselves are identical.
- **The overlap rules** (§4) and the review/merge policy (`AGENTS.md` §3a).
- **The no-coordinator decision** (ADR-0019) — ADR-0021 only replaces the *claim
  mechanics*; it does not reintroduce a role.
- **Your branches, PRs, and commits.** The lease ledger lives in
  `refs/coord/leases/*`, which is disjoint from `refs/heads/*`.

## 4. What the transition removes

These are gone and should not be re-introduced:

- The `CLAIM:` / `LEASE:` / `TAKEOVER:` **comment lines** as the mechanism of
  record (the tool still *reads* them for migration, but new claims are leases).
- The **hand-maintained §8 workload table** in `docs/FOCUS_AREAS.md` and every
  `docs(coord): refresh the queue` PR. The board is generated now.
- The mandatory **start/end check-ins** on the hub issue (#38) and the
  "available to help" announcements. The lease is the check-in.
- The **`status: claimed` / `status: blocked` / `status: needs-review` labels as
  the source of truth.** They are now a **convenience mirror** kept in sync by the
  sweep; the ledger is authoritative.

## 5. Failure modes and rollback

- **The tool or the workflow is broken.** The ledger is plain git refs; you can
  always read it with `git ls-remote origin 'refs/coord/*'` and delete a stuck
  lease with `scripts/coord release --force` or, in the worst case,
  `git push origin :refs/coord/leases/<area>`. Nothing about the game
  build or the tests depends on the ledger, so a coordination outage never blocks
  a merge.
- **You want to go back.** The old protocol's documents are in git history; revert
  this change's PR. The lease refs are harmless if left in place (they are ignored
  by normal clones), and can be deleted wholesale with a single
  `git push origin --delete` per ref if desired.
- **A clock is wrong.** `scripts/coord status` shows the remaining TTL from the
  ledger's own timestamps; a nonsensical value means the writer's clock is off.
  The default 6 h TTL and 24 h cap give hours of tolerance, so this is a
  correctness hazard only in extreme cases.
- **A pre-fix client is still running.** An agent on the old per-issue layout
  (`refs/coord/leases/<area>/<issue>`) writes a ref that *blocks* the area ref
  (git cannot hold `leases/world` and `leases/world/200` at once, and it checks
  that before running an atomic transaction, so the delete cannot share the
  claim's push). `coord check` fails loudly on such a ref and the next `sweep`
  clears it, so the area frees itself; `coord claim` refuses with the exact fix,
  and `coord claim --takeover` clears the stale ref and claims the area in one
  step. Either way no agent is blocked by a ref it did not write.

## 6. Timeline

1. **Land** this change (the tool, the workflow, the docs). The ledger starts
   empty; all eight areas are free.
2. **Migrate** in-flight claims with `scripts/coord migrate --apply`. On this
   repo that was four live claims at the time of the change (render #122, platform
   #133, release #127, tactical #120); the command found and imported them.
3. **Run** normally. The sweep expires leases and rebuilds the board every 30
   minutes. After one full TTL (≤ 24 h) every live claim is a lease, and the
   legacy comment lines are historical only.
