## 1. What this project is

An open-source, from-scratch recreation of the *gameplay* of the 1993 DOS game
**Syndicate** (and elements of **Syndicate Wars**). We recreate mechanics,
feel, and systems. We do **not** ship, copy, or trace any original asset, code,
name, or trademark. See `docs/LEGAL.md`.

- **Language:** C++17
- **Game framework:** SDL2 + `SDL_Renderer` (see ADR-0006; Cocos2d-x was
  dropped as too heavy — see ADR-0001)
- **Build:** CMake ≥ 3.15 + `scripts/*.sh`
- **Primary platform:** Debian-based Linux (Linux Mint, Ubuntu). macOS and
  Windows are supported and documented, but not tested regularly.
- **License:** MIT (see `LICENSE`)

## 1b. Target machines — keep it lightweight

The game must run on **very old, low-end hardware**: think a computer that was
low-end 15 years ago. It does **not** need to run on a 386, but it must not
require a modern GPU or lots of RAM.

Practical rules:

- Prefer a software-rendered path (we use `SDL_Renderer`, which can fall back to
  the software backend) over a hard OpenGL/Vulkan requirement.
- Keep the binary and its dependencies small; avoid pulling in large frameworks.
- Keep per-frame work cheap: no per-pixel effects on the critical path, prefer
  tiles/sprites and cached surfaces.
- Do not assume a dedicated GPU, large VRAM, or a fast CPU.
- Profile assumptions: target smooth play on integrated graphics from ~2010.

## 4. Golden rules of the codebase

These are non-negotiable unless an ADR supersedes them.

1. **Engine-agnostic core.** All game logic (math, world model, pathfinding,
   combat rules, economy) lives in `src/core/` and must **not** include
   `SDL.h`. It must build and be unit-testable with a plain compiler.
   Rendering/input/audio live behind the engine layer (`src/game/`, `src/world/`,
   `src/entities/`).
2. **Core is pure and testable.** No global mutable state in `core`. Prefer
   free functions and small value types. Deterministic where possible.
3. **No engine types in public core APIs.** Use our own `Vec2`/`TilePos`, not
   `SDL types`, in `core`.
4. **Simulation ≠ rendering.** Gameplay ticks on a fixed timestep; the renderer
   interpolates. Never derive gameplay outcomes from frame rate.
5. **Tests are real.** Unit tests call real code paths. No mocks unless the
   dependency genuinely cannot run headless — and then justify it in a comment.
6. **Every new core system ships with tests** in `tests/`.
7. **Data over code.** Weapons, agents, missions, and balance values live in
   data files (see §7), not hard-coded constants, so multiple agents can extend
   content without merge conflicts in C++.
8. **Assets are original or explicitly licensed.** No ripped sprites, sounds,
   fonts, or names. See `docs/ASSETS.md`.
9. **Warnings are errors in spirit.** The build uses `-Wall -Wextra -Wpedantic`.
   Do not merge code that adds warnings.
10. **Small commits, descriptive messages** (§8).

## 5. Repository layout

```
src/
  core/        # engine-agnostic game logic (NO SDL includes)
    math/      # vectors, isometric transforms, fixed timestep helpers
    world/     # tile grid model, pathfinding (A*)
    sim/       # future: agents, combat, AI, economy (headless)
  game/        # SDL2 app shell: main loop, Game, rendering, input
tests/         # unit tests for src/core (plain C++, run via ctest)
docs/          # ARCHITECTURE, BUILD, CONTRIBUTING, COORDINATION, ROADMAP,
               # LEGAL, ASSETS, DECISIONS, DEVELOPMENT_ENVIRONMENT, SETUP_*
scripts/       # bootstrap/fetch/build helpers
assets/        # original/licensed game assets (see docs/ASSETS.md)
```

**The boundary rule in one line:** if it can be decided without drawing a pixel
or reading input, it belongs in `src/core/`.

**Engine layer rule:** `src/game/` may include `<SDL.h>`; `src/core/` never may.

## 8. Build & test (canonical commands)

```bash
# Full build: core + tests + the SDL2 game target.
./scripts/build.sh

# Or manually (Debian/Ubuntu: sudo apt-get install libsdl2-dev)
cmake -S . -B build -DFOSS_BUILD_GAME=ON
cmake --build build -j
ctest --test-dir build --output-on-failure

# Core-only build + tests (no SDL needed) — this is what CI runs.
cmake -S . -B build-core -DFOSS_BUILD_GAME=OFF
cmake --build build-core -j
ctest --test-dir build-core --output-on-failure
```

CI runs two jobs: a **core + game** job (installs `libsdl2-dev`, builds with
`-DFOSS_BUILD_GAME=ON`, runs `ctest`, which includes the headless `game_smoke`
test) and a **core-only** job (no graphics deps). If your change touches
`src/core/` or `tests/`, both must pass. If it touches `src/game/`, also run the
game target locally and note the result in the PR.
